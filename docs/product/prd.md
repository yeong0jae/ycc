# 공연 소통 서비스 기획서

## 한 줄 정의

공연(콘서트·페스티벌)마다 주최측의 공지와 관객의 목소리가 제때 오가는 곳

공연 날 필요한 공식 정보(공지·타임테이블·현장 안내)를 한곳에서 보고, 표를 가진 관객의 건의가 주최측에 닿게 한다.

관객은 갈 공연에 **참여**하고, 홈에 모인 공연으로 들어가 그 공연의 **공연 홈**(공지·타임테이블·건의·커뮤니티)을 쓴다. 보는 데는 로그인이 필요 없다.

## 방향을 바꾼 이유

이전에는 공연 날 브이로그(로그)와 동행 매칭을 중심에 뒀다. 하지만 둘 다 많은 사람이 모여야 의미가 생기고, 혼자 만들고 운영하기에 해결이 어렵다고 판단했다.

대신 **주최측과 관객 사이의 소통 공백**을 푼다. 이 문제는 공연 하나, 주최측 하나만 붙어도 바로 가치가 생긴다.

## 누구의 문제인가

- **관객**: 공연 당일 무슨 일이 일어나는지 빨리 알고 싶고, 불편한 점을 말할 곳이 필요한 사람
- **주최측**: 공지를 관객 모두에게 빠르게 전하고, 관객 반응을 한곳에서 보고 싶은 사람

## 문제와 현재 대안

### 1. 주최측의 목소리가 관객에게 닿지 않는다

우천으로 페스티벌이 중단됐는데 공지가 늦고 흩어져서, 관객은 현장에서 상황을 모른 채 기다렸고 주최측은 크게 비판받았다. 우천 외에도 공지할 일은 많다. 예: 입장 시간 변경, 출연 취소, 타임테이블 변경, 굿즈 판매 안내, 현장 부스·푸드트럭 위치.

| 현재 대안 | 쓰는 방식 | 불편한 점 |
| --- | --- | --- |
| 공식 인스타그램 | 피드·스토리로 공지 | 스토리는 24시간 뒤 사라지고, 팔로우 안 한 관객은 못 봄 |
| 예매처 공지 | 예매 페이지 공지사항 | 공연 당일엔 아무도 다시 안 봄 |
| 공식 홈페이지 | 공지 게시판 | 모바일로 찾기 어렵고 업데이트가 느림 |
| 현장 방송·전광판 | 현장에서 안내 | 현장에 있는 사람만, 들리는 범위에서만 |

### 2. 관객의 목소리가 주최측에 닿지 않는다

불편을 말할 곳이 SNS 댓글, 커뮤니티 글, 예매처 후기로 흩어져 있다. 주최측은 무엇이 진짜 관객의 목소리인지 구분하기 어렵다.

### 3. 공연 날 필요한 정보가 흩어져 있다

타임테이블, 현장 지도(무대·부스·푸드트럭·화장실), 공지가 각기 다른 곳에 있다.

## 참여와 공연 홈

```
찾기 → 공연 상세(정보) ─[참여하기]→ 버튼이 [홈에서 보기]로 바뀜 ─누르면→ 홈
홈 = 참여한 공연 목록 ─────────────┐
현장 QR ──────────────────────────┼─▶ 공연 홈: 공지 · 타임테이블 · 건의 · 커뮤니티
공유 링크 ────────────────────────┘        누구나, 로그인 없이 볼 수 있음
```

- **공연 상세**는 공연을 고르는 곳(포스터·기간·가격·장소, 예매처, 참여하기). **공연 홈**은 그 공연에 참여하는 곳이다.
- **보는 건 누구나**: 공연 홈의 공지·타임테이블·건의·커뮤니티는 로그인 없이 읽는다. "내 돈 내고 왔는데 공지 보려고 가입해야 하나"가 되면 안 된다.
- **참여는 로그인 없이**: 참여한 공연은 이 기기에 저장되고 홈에 모인다. 현장 QR로 들어오면 자동으로 참여된다(되돌리기 가능).
- **로그인은 꼭 필요할 때만**: 커뮤니티 글쓰기, 예매 인증, 다른 기기에서도 홈 보기. 로그인하면 이 기기에서 참여한 공연이 계정으로 합쳐진다.
- 참여하지 않은 사람도 긴급 공지를 놓치지 않게, 공연 상세에 최근 긴급 공지 한 줄을 보여 준다.

## 사용자와 권한

| 사용자 | 들어오는 곳 | 할 수 있는 것 |
| --- | --- | --- |
| 비회원 | 일반 페이지 | 공연 목록·검색·상세, 참여(이 기기), 공연 홈 보기(공지·타임테이블·건의·커뮤니티) |
| 현장 관객 | 현장 QR | 비회원 기능 + 자동 참여 + 로그인 없이 그 공연에 건의 쓰기 (공연 기간에만) |
| 회원 | 카카오 로그인 | 비회원 기능 + 커뮤니티 글쓰기 + 참여한 공연을 계정에 저장 |
| 예매 인증 회원 | 공연별 예매 인증 | 회원 기능 + 그 공연에 건의 쓰기 |
| 주최측 | 주최측 페이지 (`/organizer`) | 맡은 공연의 공지 쓰기, 건의 보기·답하기, 현장 QR 받기 |
| 개발자 | 개발자 페이지 (`/dev`) | 공연 검수, 타임테이블 작성, 주최측 계정 발급, 예매 인증 검수 |

- **주최측 페이지**는 주최측이 쓰는 곳, **개발자 페이지**는 서비스를 만드는 사람(나)이 쓰는 곳이다.
- 일반 페이지에는 카카오 로그인만 보인다. 주최측 로그인은 `/organizer`로 들어와야만 보인다.
- 주최측 계정은 개발자가 직접 만들어 준다.
- 건의는 누가 썼는지 표시한다: **예매 인증** 또는 **현장 QR**. 주최측이 믿을 만한 목소리를 구분할 수 있게.

## 데이터

- **공연**: 콘서트·페스티벌. KOPIS에서 수집하고 개발자가 검수해 띄운다. 종류를 나눠서 볼 수 있다
- **유저**: 회원(카카오), 주최측 계정, 개발자
- **참여**: 공연 + 기기(로그인 없이) 또는 회원. 로그인하면 기기 참여가 회원 참여로 합쳐짐
- **예매 인증**: 회원 + 공연. 예매 내역 캡처를 개발자가 확인
- **공지**: 공연 + 주최측. 종류(긴급·일정 변경·안내), 제목, 내용(선택), 이미지(선택, 여러 장), 올린 시각·고친 시각
- **타임테이블**: 공연 + 날짜 + 무대 + 시간 + 출연. 개발자가 개발자 페이지에서 작성
- **건의**: 공연 + 작성 경로(예매 인증 회원 / 현장 QR). 내용, 주최측 답변
- **현장 QR**: 공연별로 발급. 공연 기간에만 유효
- **커뮤니티 글**: 공연 + 회원. 종류(자랑·OOTD·질문 등), 내용

## 해결책 (최소 기능)

1. **공연 찾기**: 콘서트 / 페스티벌을 나눠 보기, 검색, 지도, 공연 추가 요청 (지금 찾기 기능 기반)
2. **공연 상세**: 포스터·기간·가격·장소, 예매처, **참여하기**. 긴급 공지가 있으면 한 줄로
3. **홈**: 참여한 공연. 오늘 공연이 맨 위에 최근 공지와 함께, 그 아래 다가오는 공연
4. **공연 홈**: 공지 · 타임테이블 · 건의 · 커뮤니티 탭. 긴급 공지는 맨 위에 고정. 위쪽 공연 이름을 누르면 공연 상세
5. **공지**: 주최측이 올리면 공연 홈에 바로 보인다. 종류(긴급·일정 변경·안내), 긴 글, 이미지(카드뉴스 한 장만으로도). 긴급은 검은 카드로 눈에 띄게
6. **타임테이블**: 날짜·무대별 시간표
7. **예매 인증**: 예매 내역 캡처 → 개발자 확인 → 그 공연에 건의 가능
8. **건의**: 예매 인증 회원, 또는 현장 QR을 찍은 관객(로그인 없이)이 작성. 누구나 조회, 주최측 답변
9. **현장 QR**: 주최측이 주최측 페이지에서 공연별 QR을 받아 현장(입구·부스·화장실 등)에 붙인다. 찍으면 그 공연의 공연 홈이 열리고 자동으로 참여된다. 건의는 로그인 없이 바로 쓴다
10. **커뮤니티**: 공연마다 글 목록. 자랑·OOTD·질문 등 종류. 회원만 작성
11. **주최측 페이지** (`/organizer`): 주최측 로그인, 공지 작성, 건의 답변, 현장 QR 받기
12. **개발자 페이지** (`/dev`): 공연 검수, 공연 추가 요청 확인, 타임테이블 작성, 주최측 계정 발급, 예매 인증 검수

만들지 않는 것: 공연날 로그(브이로그), 동행(매칭도 커뮤니티 글 종류도 일단 뺌), 자체 채팅, 앱(네이티브).

## 성공 기준

- 주최측이 공지를 올린 뒤 관객이 보기까지 걸리는 시간
- 공연당 참여 수(찾기에서 / 현장 QR로), 그중 로그인한 비율
- 공연당 공지 조회 수, 공연 당일 방문자 수
- 예매 인증 회원 수, 공연당 건의 수(예매 인증 / 현장 QR)와 주최측 답변 비율
- 주최측 계정이 실제로 공지를 올린 공연 수

## 열린 질문

- **공지 알림**: 공지가 "닿으려면" 관객이 앱을 열지 않아도 알아야 한다. 받는 사람은 그 공연에 참여한 기기·회원. 웹 푸시는 계정 없이 기기에 묶여 참여와 잘 맞지만, 아이폰은 홈 화면에 추가한 경우만 가능. 카카오 알림톡·문자는 연락처가 필요
- **기기 저장의 한계**: 로그인 없는 참여는 브라우저 기록을 지우거나 다른 브라우저(예: 카카오톡 QR 스캐너 안의 브라우저)로 열면 홈에 안 보인다. 그때 "로그인하면 어디서든 보여요"를 어떻게 자연스럽게 권할지
- **현장 지도**: 무대·부스·푸드트럭·화장실 위치를 지도로 보여주는 기능을 처음부터 넣을지, 공지(이미지)로 대신할지
- **주최측 확보**: 첫 주최측을 어떻게 데려올지. 그 전까지는 개발자가 공식 SNS 공지를 옮겨 적을지
- **커뮤니티 관리**: 신고·차단·숨김을 누가 어떻게 처리할지
- **예매 인증 방식**: 캡처 검수의 부담과 위조 가능성. 공연이 많아지면 어떻게 확장할지

## 보류 아이디어

- **공연날 로그(브이로그)**: 공연 날 짧은 컷을 찍어 하나의 영상으로
- **동행**: 같은 회차 관객끼리 연결(매칭이든 커뮤니티 글 종류든). 나중에 커뮤니티에 붙이기 쉬움
- **관람 기록·연대기**: 다녀온 공연을 모아 보는 기능
- **한일 확장**: 일본 페스티벌 일정, 한일 팬 소통
