# tasks-002: KOPIS 콘서트 데이터 연동

## 목표

더미 데이터를 걷어내고, KOPIS 공개 API에서 실제 콘서트 정보를 받아 목록·상세에 보여준다.

## 범위

- 포함: KOPIS 목록·상세 조회, 하루 한 번 동기화, `shows` 테이블 구조 변경, 화면 반영
- 제외: 공연명에서 아티스트 이름 추출, 직접 입력(관리자 화면), 포스터 이미지 자체 저장, 회차별 예매

## 체크리스트

### 0. 결정

- [x] 데이터 출처: KOPIS 공개 API (인증키는 루트 `.env`의 `KOPIS_API_KEY`)
- [x] 조회 범위: 대중음악(`shcate=CCCD`), 오늘부터 6개월, 서울·경기(`signgucode` 11·41). 한 번에 31일까지만 조회되므로 31일씩 나눠 받음
- [x] 제외 대상: 오픈런(`openrun=Y`), 기간이 31일 넘는 공연(종료일 오입력 포함), 페스티벌(`festival=Y`), 팬미팅(공연명에 "팬미팅"·"FAN MEETING"·"MEET & GREET")
- [x] 출연: 빼기 (KOPIS 출연진이 비어 있거나 본명이라 믿기 어려움)
- [x] 동기화 주기: 하루 한 번 + 서버 시작 시 1회. 이번 결과에 없는 공연은 삭제
- [x] 호출 제한: 1초에 10회를 넘으면 차단되므로 호출 간격 0.2초, 간헐적 차단(400)은 최대 5번 재시도
- [x] 출처 표기: 하지 않음

### 1. 데이터

- [x] `shows` 변경: `kopis_id` 추가(고유), `schedule_guide`·`price_guide` 추가, `lineup` 삭제, `official_url` 비워도 되게
- [x] 더미 데이터 삭제
- [x] KOPIS 응답(XML) → `Show` 변환: 공연명, 기간, 공연장, 포스터, 예매처 링크(`relates`의 첫 번째), 회차 안내(`dtguidance`), 가격 안내(`pcseguidance`)

### 2. 동기화

- [x] KOPIS 목록 조회: 페이지를 끝까지 넘겨 받기
- [x] 공연별 상세 조회
- [x] `kopis_id` 기준으로 없으면 추가, 있으면 갱신
- [x] `compose.yaml`에서 `KOPIS_API_KEY`를 백엔드로 전달
- [x] 테스트: KOPIS 응답 XML 샘플로 변환·필터 검증 (실제 API 호출 없이)

### 3. 화면

- [x] 상세: 출연 → 회차 안내·가격 안내로 교체
- [x] 상세: 공식 사이트 버튼은 링크가 있을 때만

### 4. 완료 기준

- [x] `docker compose up` 후 목록에 실제 서울·경기 콘서트가 다가오는 순으로 나온다
- [x] 상세에서 예매처 링크로 이동된다
- [x] 페스티벌·팬미팅이 목록에 없다

## 알려진 문제

- KOPIS 포스터 주소가 `http://`라서, `https`로 배포하면 브라우저가 이미지를 막을 수 있다. 배포할 때 이미지 저장 또는 프록시로 해결한다.
