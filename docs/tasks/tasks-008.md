# tasks-008: 공연 데이터 정리 (콘서트 다시 수집 + 페스티벌 / 콘서트 나눠 보기)

## 목표

PRD의 "공연 = 콘서트 · 페스티벌"에 맞게 콘서트를 다시 수집하고, 찾기에서 페스티벌과 콘서트를 나눠 볼 수 있게 한다. 이후 공지·타임테이블·건의가 모두 이 공연 데이터에 붙는다.

## 범위

- 포함: KOPIS 콘서트 수집, 공연 종류(페스티벌 / 콘서트) 저장, 바뀐 공연만 받는 동기화, 찾기의 종류 탭, 검수 화면의 종류 구분
- 제외: 관리자(주최측) 계정·권한과 개발자 페이지 분리(tasks-009 예정), 공지, 타임테이블, 건의, 커뮤니티, 아티스트 데이터

## 체크리스트

### 0. 결정

- [x] 종류 판정: KOPIS 축제 목록(`/prffest`)에 있으면 페스티벌, 대중음악 공연 목록(`/pblprfr`)에만 있으면 콘서트
- [x] 콘서트 범위: 페스티벌과 같게 전국(해외 제외), 지난 3개월 ~ 앞으로 6개월. 팬미팅·오픈런은 지금처럼 뺌
- [x] 기간 제한: 페스티벌·콘서트 모두 14일 넘는 공연은 뺌(지금은 31일). 실제 데이터에서 콘서트는 97%가 3일 이내, 가장 긴 진짜 공연은 콘서트 9일·페스티벌 11일(옥토버페스트 10일, PEER 꽃마당 FESTA 11일). 그보다 긴 건 여러 공연을 묶은 시리즈·패키지
- [x] 패키지표 제외: 이름이 "[패키지]"로 시작하면 뺌. 개별 공연이 따로 등록돼 있어 중복
- [x] 수집량: 2026년 11월 한 달 기준 전국 275건(서울 155, 경기 23). 9개월이면 약 2천 건. 지금처럼 매번 상세를 전부 다시 받으면 하루 2천 번 조회, 10분 안팎
- [x] 동기화 방식: 목록은 매번 전체를 받고(가벼움, 취소된 공연을 찾는 데 필요), 상세는 마지막 동기화 이후 등록·수정된 공연과 새 공연만 다시 받음. KOPIS 목록 조회의 `afterdate`(그 날짜 이후 등록·수정분만) 사용. 11월 공연 100건 중 하루 사이 바뀐 건 13건
- [x] 동기화 시점: 매일 새벽 4시 + 서버가 켜질 때. 둘 다 바뀐 것만 받음. 마지막 성공 기록이 없거나 공연이 하나도 없으면 전체를 받음
- [x] 찾기: 목록·지도 모두 맨 위 왼쪽에 페스티벌 / 콘서트 알약 토글, 오른쪽에 목록 / 지도 토글. 목록은 그 아래 줄에 검색창. 기본은 페스티벌. 주소에 남겨서(`?kind=concert`) 새로고침해도 유지
- [x] 콘서트 검수: 콘서트는 처음 들어올 때 바로 띄움, 이상한 것만 검수 화면에서 무시. 페스티벌은 지금처럼 대기로 시작
- [x] 지도: 고른 종류의 공연장만 표시. 왼쪽 위에 목록/지도 토글과 같은 모양의 페스티벌 / 콘서트 토글(오른쪽 위는 목록/지도 토글 그대로). 목록과 지도가 고른 종류를 함께 씀(`?kind=` 유지)

### 1. 데이터

- [ ] `shows.kind`: FESTIVAL / CONCERT. 기존 공연은 모두 FESTIVAL
- [ ] 같은 공연이 두 목록에 다 있으면 페스티벌로 저장
- [ ] 동기화 기록: 마지막으로 성공한 동기화 시각

### 2. 백엔드

- [ ] KOPIS: 대중음악 공연 목록 조회 추가(지역 조건 없이 전국)
- [ ] 동기화: 축제 목록과 공연 목록을 함께 받아 종류를 정하고, 상세는 새 공연과 마지막 동기화 이후 바뀐 공연만 조회
- [ ] 동기화 기록: 성공하면 시각 저장, 실패하면 저장하지 않아 다음 번에 그 이후분부터 다시 받음
- [ ] 동기화 정리: 이번 결과에 없는 앞으로의 공연은 종류와 상관없이 지금처럼 지움
- [ ] 검수 상태: 새로 들어오는 콘서트는 띄움, 페스티벌은 대기. 이미 있는 공연의 검수 상태는 동기화가 바꾸지 않음
- [ ] 공연 검색 API: 종류 조건 추가
- [ ] 검수 API(개발자 페이지): 종류 조건 추가
- [ ] 테스트: 종류 판정(두 목록에 다 있는 공연 포함), 14일 넘는 공연·패키지표 제외, 바뀐 공연만 상세 조회, 첫 동기화는 전체 조회, 실패 시 기록 유지, 종류별 검색, 콘서트는 바로 띄움

### 3. 프론트

- [ ] 찾기: 위쪽 페스티벌 / 콘서트 알약 토글(목록 / 지도 토글과 같은 모양, 찾기 레이아웃에 고정), 그 아래 검색창, 종류별 검색, 오늘 점선·스크롤 위치 복원은 종류마다
- [ ] 공연 카드·상세: 문구를 "페스티벌" 대신 종류에 맞게
- [ ] 검수 화면(개발자 페이지): 종류 필터
- [ ] 지도: 고른 종류의 공연장만 표시, 목록 ↔ 지도 오갈 때 종류 유지

### 4. 완료 기준

- [ ] 찾기에서 콘서트 탭을 누르면 콘서트만, 페스티벌 탭을 누르면 페스티벌만 보인다
- [ ] 콘서트를 고른 채 지도로 가면 콘서트 공연장만 보이고, 다시 목록으로 와도 콘서트가 선택돼 있다
- [ ] 같은 공연이 두 탭에 동시에 나오지 않는다
- [ ] 동기화를 다시 돌려도 종류와 검수 상태가 바뀌지 않는다
- [ ] 첫 동기화가 끝까지 돌고, 걸린 시간을 확인했다
- [ ] 다음 동기화부터 상세 조회 수가 바뀐 공연 수만큼으로 줄어든 걸 로그로 확인했다
