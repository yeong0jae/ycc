# tasks-009: 주최측 계정과 주최측 페이지(`/organizer`) 틀

## 목표

주최측이 `/organizer`로 로그인해 자기 공연 화면에 들어올 수 있게 한다. 이후 공지·건의·현장 QR이 모두 이 화면에 붙는다. 주최측 계정은 공연마다 하나씩, 개발자가 개발자 페이지에서 만들어 준다.

## 범위

- 포함: 주최측 계정(일반 회원·개발자와 분리), 계정마다 공연 하나 연결, 개발자 페이지의 "주최측" 탭, `/organizer` 로그인·로그아웃, `/organizer/shows/{id}` 화면 틀(메뉴 자리 + 공연 기본 정보)
- 제외: 공지·건의·현장 QR의 실제 기능(tasks-010 이후), 알림, 일반 페이지에 "공식" 표시, 주최측이 스스로 가입하기, 비밀번호 찾기
- 이미 끝남: `/dev` 분리, 개발자 로그인, 개발자 공통 헤더(2026-10-19)

## 체크리스트

### 0. 결정

- [x] 계정 정보: 아이디, 비밀번호, 표시 이름(주최사·기획사 이름) 셋만. 연락처는 안 받음
- [x] 비밀번호: 개발자가 정해서 주최측에 알려 준다. 주최측이 바꾸는 기능은 없음. 잊으면 개발자에게 말하고, 개발자가 개발자 페이지에서 새로 정해 준다
- [x] 계정 ↔ 공연: 일대일. 계정은 공연마다 하나. 만들 때 공연을 고르고, 한 공연에 계정은 하나만
- [x] 연결할 수 있는 공연: 띄움(VISIBLE)인 공연만. 개발자 페이지에서 이름으로 검색해 고름
- [x] 비활성화: 계정을 지우지 않고 비활성화. 비활성화한 계정은 로그인할 수 없음. 나중에 그 계정이 쓴 공지·답변이 남아야 해서
- [x] 로그인 유지: 개발자 로그인과 같은 세션 방식, 30분 동안 아무것도 안 하면 풀림
- [x] 로그인 시도 제한: 같은 아이디로 5번 틀리면 10분 동안 막기
- [x] 첫 화면: `/organizer`로 로그인하면 그 계정의 공연 화면(`/organizer/shows/{id}`)으로 바로 감
- [x] 공연 화면 틀: 시안처럼 위쪽 검은 줄(공연 이름, 계정 이름, 로그아웃) + 왼쪽 메뉴(공지 · 건의 · 현장 QR). 메뉴는 "곧 열려요"로 비활성. 이번엔 공연 기본 정보(기간·장소·포스터)만 보여줌
- [x] 개발자가 주최측 화면 보기: 따로 안 만듦. 개발자가 계정을 알고 있으니 그 계정으로 로그인해서 봄

### 1. 데이터

- [ ] `organizers`: 아이디(고유), 비밀번호 해시, 표시 이름, 공연(고유, 한 공연에 계정 하나), 활성 여부, 만든 시각
- [ ] 로그인 실패 기록: 아이디별 실패 횟수와 잠금 끝나는 시각

### 2. 백엔드

- [ ] 주최측 로그인·로그아웃·내 정보: `/api/organizer/login`, `/api/organizer/logout`, `/api/organizer/me`(계정 이름과 공연 ID). 세션에 주최측 ID를 따로 저장(카카오·개발자 로그인과 섞이지 않게)
- [ ] `/api/organizer/**`는 주최측 로그인이 있어야 하고, 공연별 API는 그 계정의 공연만(아니면 403)
- [ ] 로그인 시도 제한, 비활성화한 계정은 로그인 거절
- [ ] 개발자용 주최측 관리 API(`/api/dev/organizers`): 목록, 만들기(아이디·비밀번호·표시 이름·공연), 비밀번호 다시 정하기, 공연 바꾸기, 비활성화·다시 활성화, 고를 공연 검색(띄움만, 이미 계정이 있는 공연 제외)
- [ ] 공연 기본 정보: `/api/organizer/shows/{id}`
- [ ] 테스트: 로그인(성공·틀림·비활성화·잠금과 풀림), 카카오·개발자 세션으로는 401, 다른 공연은 403, 한 공연에 계정 두 개는 거절, 띄움이 아닌 공연은 연결 거절, 개발자 관리 API

### 3. 프론트

- [ ] 개발자 페이지 "주최측" 탭: 계정 목록(표시 이름·아이디·공연·활성 여부), 계정 만들기, 비밀번호 다시 정하기, 공연 바꾸기, 비활성화·다시 활성화
- [ ] `/organizer` 로그인 화면: 아이디·비밀번호. 일반 페이지 어디에도 링크하지 않음. 로그인하면 공연 화면으로 이동
- [ ] `/organizer/shows/{id}` 화면 틀: 위쪽 줄(공연 이름·계정 이름·로그아웃), 왼쪽 메뉴(공지·건의·현장 QR 비활성), 공연 기본 정보

### 4. 완료 기준

- [ ] 개발자 페이지에서 공연을 골라 주최측 계정을 만들면, 그 계정으로 `/organizer`에 로그인해 그 공연 화면으로 바로 들어간다
- [ ] 다른 공연 주소를 직접 쳐도 403
- [ ] 비밀번호를 5번 틀리면 잠기고, 10분 뒤 풀린다
- [ ] 비활성화한 계정은 로그인할 수 없고, 다시 활성화하면 된다
- [ ] 일반 페이지에는 주최측 로그인이 어디에도 보이지 않는다
