# tasks-010: 참여 · 홈 · 공연 홈 · 공지

## 목표

관객이 로그인 없이 공연에 참여하고, 홈에 모인 공연으로 들어가 그 공연의 공연 홈에서 공지를 본다. 주최측은 `/organizer`에서 공지를 올리고, 올리면 공연 홈에 바로 보인다. 우천 중단 같은 긴급 공지는 눈에 띄게 보여 현장 관객이 상황을 바로 알 수 있게 한다.

## 범위

- 포함: 공연 상세의 참여하기(로그인 없이, 이 기기에 저장), 홈(참여한 공연), 공연 홈 틀(탭: 공지 · 타임테이블 · 건의 · 커뮤니티), 공지 쓰기·고치기·지우기(주최측 페이지), 공지 이미지, 공연 홈의 공지 보기, 공연 상세의 긴급 공지 한 줄, 공연 홈을 열어 둔 동안 새 공지 반영
- 제외: 알림(웹 푸시·알림톡·문자), 타임테이블·건의·커뮤니티 탭 내용(탭만 "곧 열려요"), 현장 QR(자동 참여는 QR 작업에서), 로그인 시 기기 참여를 계정으로 합치기, 공지 읽음 수 통계
- 시안: 공지 시안 캔버스(claude.ai/artifact/ET6aBXRm51BLqZb2kWUoZc)
  - "참여" 줄: J-1 공연 상세 · 참여하기, J-2 홈 · 참여한 공연, J-3 홈 · 아직 없음, J-4 공연 홈 · 공지
  - 주최측: "주최측 · 공지 (데스크톱)", "주최측 · 공지 쓰기 (휴대폰)"
  - 공지 목록 모양은 이전 캔버스 11-2(줄로 나눈 목록, 밑줄 글자 탭)를 따름
- 실제 공지 모양(2026-10-20 사용자 예시): ① 제목 + 줄바꿈·이모지가 섞인 긴 글, 짧으면 한두 줄 ② 글 없이 카드뉴스 이미지 한 장(예: 우천 공연 취소 안내). 둘 다 흔함

## 체크리스트

### 0. 결정

참여 · 홈 · 공연 홈

- [x] 이름: "참여". 공연별 공간은 "공연 홈"(처음엔 "공연 공간", 2026-10-20 변경). 공연 상세 아래쪽 버튼이 예매 인증 대신 `[예매처 ↗] [+ 참여하기]`
- [x] 보는 건 누구나: 공연 홈(공지·타임테이블·건의·커뮤니티)은 로그인 없이 볼 수 있음. 참여는 보기 위한 조건이 아님
- [x] 참여는 로그인 없이: 이 기기에 저장, 홈에 바로 뜸. 참여하기를 누르면 어디로도 이동하지 않고 버튼이 "홈에서 보기"로 바뀜. 그걸 누르면 홈으로. 홈에서 공연을 누르면 공연 홈(2026-10-20 변경, 전엔 바로 공연 홈으로 가서 어색했음). 공연 홈 위쪽 "✓ 참여 중"을 누르면 참여 취소
- [x] 홈: 맨 위 서비스 로고. 오늘 공연은 맨 위 큰 검은 카드(진행 중, 최근 공지 한 줄, 새 공지 수), 그 아래 다가오는 공연(D-day). 아래에 "이 기기에 저장돼요. 로그인하면 다른 기기에서도 보여요." 비었을 때는 "갈 공연에 참여해 보세요" + 공연 찾아보기
- [x] 공연 상세의 긴급 공지 한 줄: 참여하지 않은 사람도 놓치지 않게. 누르면 공연 홈
- [x] 공연 홈 탭: 공지 · 타임테이블 · 건의 · 커뮤니티(밑줄 글자 탭). 이번엔 공지만 열고 나머지는 "곧 열려요". "정보" 탭은 두지 않고, 위쪽 포스터·제목·날짜를 누르면 공연 상세로(2026-10-20)
- [x] 공연 홈 아래쪽: `[예매 인증] [건의 남기기]`. 이번엔 둘 다 "곧 열려요"
- [x] 주소: 추천은 공연 상세 `/shows/{id}` 그대로, 공연 홈은 탭마다 `/shows/{id}/notices`, 나중에 `/shows/{id}/timetable` 등. 탭마다 주소가 있어 링크로 나눠 줄 수 있음
- [x] 기기 저장: 브라우저 저장소(localStorage)에 공연 ID 목록. 회원도 이번엔 똑같이 기기에 저장. 로그인 시 계정으로 합치기는 나중에. 서버에는 아직 안 보냄(나중에 알림·로그인 합치기 때 기기 ID를 붙임). 홈은 그 ID들로 공연 정보를 받아 그림
- [x] 참여한 공연이 끝나면: 홈에서 "지난"으로 아래로 내리고 흐리게, END 배지. 자동으로 빼지는 않음(시안 J-2)

공지

- [x] 종류: 긴급 · 일정 변경 · 안내. 긴급은 검은 카드 + 라임 칩, 일정 변경은 크림 칩, 안내는 회색 칩
- [x] 쓰는 칸: 종류, 제목(필수), 내용(선택, 줄바꿈·이모지 그대로), 이미지(선택). 내용과 이미지 중 하나는 있어야 함
- [x] 길이: 추천은 제목 60자, 내용 3,000자
- [x] 이미지: 추천은 공지 하나에 최대 4장, 장당 10MB, jpg·png·webp. 올릴 때 브라우저에서 긴 변 2,000px 이하 JPEG로 줄여서 보냄(휴대폰 사진의 회전 정보를 브라우저가 바로잡아 줌). 서버는 진짜 이미지인지와 크기만 확인. 관객 화면에서는 폭에 맞춰 크게, 누르면 원본 크기로
- [x] 이미지 저장소: 추천은 GCS 버킷 하나(공개 읽기), 업로드는 백엔드를 거쳐서(주최측 로그인 확인). terraform에 버킷과 VM 쓰기 권한 추가. 로컬에서는 디스크 폴더에 저장
- [x] 공연 홈 맨 위: 가장 최근 긴급 공지를 검은 카드로 고정. 나머지는 그 아래 줄로 나눈 목록에 최신순. 공지마다 종류 칩 · 시각 · 제목 · 내용 · 이미지 · "주최측 · {표시 이름}"
- [x] 긴급 공지가 맨 위에 머무는 시간: 추천은 더 새로운 긴급 공지가 올라올 때까지. 따로 "해제"는 안 만듦. 상황이 끝나면 주최측이 안내 공지를 올리는 흐름
- [x] 긴 글 보기: 추천은 목록에서 내용 4줄까지만 보이고 "더 보기"로 펼치기. 맨 위 긴급 공지는 전부 펼친 채로
- [x] 고치기·지우기: 둘 다 됨. 고치면 "수정됨"을 같이 보여 줌. 지우면 관객 화면에서 바로 사라짐(기록은 남김)
- [x] 새 공지 반영: 추천은 공연 홈을 화면에 띄워 둔 동안 30초마다 확인, 다른 탭으로 가 있는 동안은 확인 안 함
- [x] 시각 표시: "14:20 · 3분 전", 하루가 지나면 "어제 18:00", 그 전은 "10.20"
- [x] 주최측 쓰기 화면: 데스크톱은 쓰기 + 오른쪽 "관객에게 이렇게 보여요" 미리보기 + 올린 공지 목록(고치기·지우기). 휴대폰도 같은 칸을 세로로(현장에서 급하게 올리는 경우)
- [x] 주최측이 아직 없는 공연: 추천은 따로 안 만듦. 개발자가 주최측 계정을 하나 만들어 그 계정으로 올리면 같은 효과
- [x] 공연이 끝난 뒤: 추천은 공지를 계속 보여 주고 주최측도 계속 쓸 수 있음(분실물 안내 등)

### 1. 데이터

- [x] `notices`: 공연, 쓴 주최측 계정, 종류, 제목, 내용(없을 수 있음), 올린 시각, 고친 시각, 지운 시각
- [x] `notice_images`: 공지, 순서, 저장 위치, 가로·세로 크기
- [x] 참여는 이번엔 서버에 저장하지 않음(기기 저장)

### 2. 백엔드

- [x] 주최측 공지 API: `/api/organizer/shows/{id}/notices` 목록·쓰기, `/api/organizer/shows/{id}/notices/{noticeId}` 고치기·지우기. 자기 공연만(아니면 403)
- [x] 이미지 올리기: `/api/organizer/shows/{id}/notice-images`. 형식·크기 검사, 줄여서 저장, 저장 위치 돌려줌. 공지에 붙지 않은 채 하루 지난 이미지는 지움
- [x] 관객 공지 API: `/api/shows/{id}/notices` 최신순, 지운 공지 제외, 로그인 없이. 공연 상세·홈에 쓸 "최근 긴급 공지"와 공지 수도 함께 받을 수 있게
- [x] 홈용 공연 여러 개 한 번에: `/api/shows?ids=1,2,3`(띄움인 공연만, 각 공연의 최근 공지 한 줄과 공지 수 포함)
- [x] 입력 검사: 종류 값, 제목·내용 길이, 내용이나 이미지 중 하나는 있어야 함
- [x] 이미지 저장소: 운영은 GCS, 로컬은 디스크. terraform 버킷·권한
- [x] 테스트: 쓰기·고치기·지우기, 이미지만 있는 공지, 내용도 이미지도 없으면 거절, 이미지 형식·크기 거절, 다른 공연 403, 비회원도 보기, 지운 공지는 안 보임, 최신순, 길이 제한, 여러 공연 한 번에 받기

### 3. 프론트

- [x] 공연 상세: 아래쪽 `[예매처 ↗] [+ 참여하기]`(누르면 그 자리에서 "홈에서 보기"로 바뀌고, 그걸 누르면 홈), 긴급 공지 한 줄
- [x] 홈: 서비스 로고 자리, 오늘 공연 카드, 다가오는 공연, 지난 공연, 비었을 때 화면, 기기 저장 안내
- [x] 공연 홈: 머리(포스터·진행 중·제목·날짜, 누르면 공연 상세, 참여 중 버튼), 맨 위 긴급 공지 카드, 밑줄 탭, 공지 목록(종류 칩·더 보기·이미지·수정됨), 아래쪽 버튼(곧 열려요)
- [x] 공연 홈을 띄워 둔 동안 새 공지 확인
- [x] 주최측 페이지 "공지" 메뉴 열기: 종류 · 제목 · 내용 · 이미지(끌어 놓기·사진 찍기) · 미리보기, 올린 공지 목록, 고치기·지우기. 휴대폰 화면
- [x] 공지가 캐시 때문에 늦게 보이지 않게(지금 공연 상세 정보는 몇 분 캐시됨)

### 4. 완료 기준

- [x] 로그인하지 않고 공연 상세에서 참여하기를 누르면 홈에 그 공연이 뜨고, 새로고침해도 남아 있다
- [x] 홈에서 공연을 누르면 공연 홈의 공지 탭이 열린다
- [x] 주최측이 공지를 올리면, 이미 공연 홈을 열어 둔 관객 화면에도 30초 안에 나타난다
- [x] 긴급 공지는 공연 홈 맨 위에 검은 카드로, 공연 상세에는 한 줄로 보인다
- [x] 글 없이 이미지 한 장만 올린 공지도 크게 보인다
- [x] 휴대폰으로 사진을 찍어 바로 공지로 올릴 수 있다
- [x] 고친 공지에는 "수정됨"이 보이고, 지운 공지는 관객 화면에서 사라진다
- [x] 다른 공연의 공지는 쓰거나 고칠 수 없다
- [x] 로그인하지 않은 관객도 모든 공지를 볼 수 있다
